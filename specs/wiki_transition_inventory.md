## Placement rules

- Week files go next to the week pages: `site/weeks/wXX_<name>/files/`, using the `book/wXX_*` folder names (e.g. `site/weeks/w01_laplace_part1/files/`). The site already uses `site/weeks/w07_lab_usv_pid/` and `site/weeks/w10_lab_usv_waypoint/`, so one folder per week holds both pages and files.
- Handouts used across weeks and by [oral-exam.qmd](../site/oral-exam.qmd) go in `site/handouts/` (already exists and is already linked for `nise-handout.pdf`, `partialfractionexpansion_complex.pdf`, `bodebuildingblocks2.pdf`, `bode2_nolabel.png`).
- Static files are committed directly under `site/` (see the spec decision). `.gitignore` has `*.pdf`, so scoped exceptions `!site/**/files/*.pdf` and `!site/handouts/*.pdf` are added with the first batch of files. The PDFs `oral-exam.qmd` links today are missing from the repo for this reason.
- Code that already lives in the repo is linked on GitHub, not copied. Where the repo copy differs from the wiki copy, the repo copy is newer and wins.
- Filenames are cleaned when copied: drop Confluence duplicate suffixes like ` (5)` and stale quarter suffixes like `_20_3`, `-25-1`; fix obvious typos (`impluse` → `impulse`).
- Homework solutions are public. Students get all homework solutions so they can check their work, so solutions are copied to the site like any other file. The only restricted material is the copyrighted Nise solutions manual. The author uploads it to Sakai; it goes into neither repo.
- Class material with student names (e.g. team result slides) goes to Sakai, not the public site.
- Vimeo videos are the author's own content and are moving to Microsoft Stream. Migration keeps the existing Vimeo links so pages stay complete; the author replaces them with Stream links (tracked in the spec). External videos (e.g. Prof. Hill) stay as they are.
- SharePoint/OneDrive links (NPS login) stay as links. External links stay as links.
